# Pare 技术文档

文档版本：2026-10-20  
对应产品说明和功能文档的同一版范围。

## 技术选型

| 层 | 选择 | 原因 |
|---|---|---|
| 窗口 | Tauri 2 | 安装包不含一整套 Chrome。Mac、Windows、Linux 用系统浏览器组件 |
| 界面 | Vue 3.5、`<script setup>`、TypeScript、Vite、pnpm | 与现有前端习惯一致。界面只有拖放、列表、格式和质量 |
| 本机逻辑 | Rust（Tauri 命令） | 负责选文件、调度任务、启动引擎、写结果 |
| 压图与转码 | 随安装包分发的命令行引擎 | 与 ImageOptim 使用的工具一致，不把图片送到服务端 |
| 运行时 | 不内置 Node | SVG 用 svgcleaner，不依赖 SVGO |

开发机需要 Rust 1.90 或更新、Node 20、pnpm。用户机器不需要这些。

## 总体结构

```text
界面 Vue
  选择文件、格式、质量档、引擎开关
        │
        ▼
Tauri 命令
  建立任务、限制并发、响应取消
        │
        ▼
流水线
  同格式优化  或  一次转码
        │
        ▼
引擎进程
  只从安装包资源目录启动，参数用数组传递
        │
        ▼
输出目录
  先写临时文件，成功后再放到目标路径
```

界面不直接启动压缩进程，也不拼接 shell 命令。

## 目录

```text
src/                          Vue 界面
src-tauri/                    Rust 与 Tauri 配置
src-tauri/resources/engines/  按目标平台放置的引擎二进制
engines/manifest.json         引擎名称、版本、校验和、支持的平台
docs/                         产品说明、技术文档、功能文档
```

引擎二进制体积大，不进 Git。构建时按 `engines/manifest.json` 下载固定版本，校验 SHA-256 后复制到资源目录。

## 第一版引擎

| 引擎 | 用途 | 平台 |
|---|---|---|
| oxipng | PNG 无损优化 | 三个桌面系统 |
| pngquant | PNG 有损减色，仅在有损开启时 | 三个桌面系统 |
| zopflipng | PNG 无损再压缩，慢 | 三个桌面系统 |
| jpegtran | JPEG 无损优化，去掉元数据 | 三个桌面系统 |
| jpegoptim | JPEG 有损质量上限，仅在有损开启时 | 三个桌面系统 |
| cjpeg（mozjpeg） | 把其他格式编成 JPEG | 三个桌面系统 |
| cwebp | 编成 WebP | 三个桌面系统 |
| gif2webp | 动画 GIF 编成动画 WebP | 三个桌面系统 |
| gifsicle | GIF 优化 | 三个桌面系统 |
| svgcleaner | SVG 优化 | 三个桌面系统 |
| resvg | SVG 光栅化，供转成位图 | 三个桌面系统 |

第一版不打包 pngcrush、advpng、pngout、guetzli、svgo。

每个引擎在 manifest 里写明版本号、上游地址、适用的 Rust target、可执行文件名和 SHA-256。Windows 文件名带 `.exe`。

## 两条流水线

格式是否变化，在每张图上单独判断。一批图里可以混合 JPEG 和 PNG，输出格式统一为 WebP 时，每张都走转码。

### 同格式优化

顺序执行已启用的引擎。每一步只在结果比当前文件更小时替换。全部结束后若仍不比原图小，输出目录里放原图的副本，状态为「未变小」。

临时文件放在应用缓存目录，任务结束或取消时删除。写入输出目录使用临时文件加原子替换，避免留下半张图。

JPEG，有损关闭：

```text
jpegtran -copy none -optimize -progressive
```

JPEG，有损开启：在 jpegtran 之后执行

```text
jpegoptim --strip-all --max=<质量上限>
```

默认质量上限 80。

PNG，始终：

```text
oxipng -o 4 --strip safe
```

PNG，有损开启时，在 oxipng 之后：

```text
pngquant --quality=<最低质量>-100 --skip-if-larger
```

默认最低质量 80。pngquant 认为会低于最低质量时，这一步跳过，保留上一步结果。

PNG，Zopfli 开启时最后执行 zopflipng。默认开启，单文件时间上限 60 秒。超时则保留超时前的最小结果。

GIF：

```text
gifsicle -O3
```

有损开启时追加 `--lossy=<等级>`。gifsicle 的等级越大，损失越大。界面质量 0–100 的换算：

```text
等级 = (100 - 质量) × 1.5，四舍五入
```

质量 100 不传 `--lossy`。默认有损关闭。有损打开且质量 80 时，等级为 30。

SVG：

```text
svgcleaner
```

### 一次转码

不先跑 jpegoptim、pngquant、gifsicle 有损。那些步骤和后面的编码都是有损，叠在一起会继续掉细节。

1. SVG 先用 resvg 光栅化。有 `width`/`height` 或 `viewBox` 时按该尺寸；都没有时宽度 1024，高度按比例。
2. 按目标和质量档调用一个编码器。
3. 输出为 PNG 时，编码后再跑一次 oxipng。这一步只做无损压缩。
4. 转码结果即使比原图大也写入。列表里显示变大的百分比，方便用户删掉不值得的文件。

WebP 照片档：

```text
cwebp -q 85 -m 6 -sharp_yuv -metadata icc -alpha_q 100
```

WebP 界面档：

```text
cwebp -near_lossless 60 -m 6 -metadata icc -alpha_q 100
```

`near_lossless` 的数值越大越接近原图，100 等于这一阶段不做损失。60 用于截图、界面和带文字的 PNG。

WebP 无损档：

```text
cwebp -lossless -z 9 -metadata icc -alpha_q 100
```

动画 GIF 转 WebP 使用 `gif2webp`，质量参数与上面三档的 WebP 质量对齐：照片 85，界面使用无损动画（截图动画更在意文字），无损档为 `-lossless`。

JPEG 输出使用 mozjpeg `cjpeg`：

- 照片档、界面档：质量 85，渐进式
- 无损档不提供 JPEG。JPEG 没有无损路径，界面禁用这个组合
- 透明图铺到白底后再编码，开始前在列表里说明

PNG 输出：

- 照片档、界面档：按解码后的像素做无损 PNG，再 oxipng。从 JPEG 转出时画质停在原 JPEG，文件常常变大
- 无损档：同样是无损 PNG

GIF 动画不能输出 JPEG 或 PNG。用户可改输出为 GIF 或 WebP，或勾选「只用第一帧」。默认不勾选。

## 色彩与元数据

- 编码器支持时保留 ICC。没有 ICC 时不额外做色彩转换
- 同格式 JPEG 使用 jpegtran `-copy none`，去掉 EXIF、GPS 和注释
- WebP 只传 `-metadata icc`，不保留 EXIF 和 GPS
- 第一版没有「保留全部元数据」开关

## 并发、优先级和取消

- 同时处理 4 个文件。数值可在设置里改为 1–8
- 引擎进程使用低于普通的优先级：Unix `nice`，Windows `BELOW_NORMAL_PRIORITY_CLASS`
- 取消时终止该任务的引擎进程，删除临时文件，已完整写入输出目录的文件保留
- 某个引擎缺失或退出非 0：这一步记为失败。同格式优化继续后续引擎；若没有任何一步成功，该文件状态为失败，不写入损坏结果

## 路径安全

- 引擎只从资源目录的固定文件名启动
- 参数以数组交给进程，不经过 shell
- 输出路径必须落在用户选定的输出目录内
- 不跟随输出路径里的符号链接写到目录外
- 输入可以是符号链接，读取其目标文件，输出仍用链接本身的文件名

## 界面与本机的边界

Tauri 命令：

| 命令 | 作用 |
|---|---|
| `pick_inputs` | 选择文件或文件夹 |
| `pick_output_dir` | 选择输出目录 |
| `start_batch` | 提交一批任务和当前设置 |
| `cancel_batch` | 取消当前批次 |
| `open_output_dir` | 在系统文件管理器中打开输出目录 |
| `load_settings` / `save_settings` | 读写本机设置 |

进度由 Rust 事件推到界面：`file-started`、`file-finished`、`batch-finished`。事件含文件标识、状态、输入字节数、输出字节数、使用的引擎名、错误原因。

设置存在应用数据目录的 `settings.json`。第一版字段：

```json
{
  "outputFormat": "webp",
  "preset": "photo",
  "lossy": false,
  "engines": {
    "oxipng": true,
    "pngquant": true,
    "zopflipng": true,
    "jpegtran": true,
    "jpegoptim": true,
    "gifsicle": true,
    "svgcleaner": true
  },
  "concurrency": 4,
  "gifFirstFrame": false
}
```

`pngquant` 和 `jpegoptim` 的开关只在有损开启时生效。

## 打包

Tauri 的打包目标：

| 目标 | 安装包 |
|---|---|
| macOS | `.dmg`，至少提供 Apple 芯片与 Intel |
| Windows | `.msi` 或 NSIS，x86_64 |
| Linux | `.deb` 与 AppImage，x86_64 |

Linux 包声明 WebKitGTK 依赖。AppImage 若不能内嵌该依赖，发布说明里写清系统要求。

应用不申请网络权限来上传图片。构建机下载引擎属于开发步骤，运行中的 Pare 不下载引擎。

## 日志

默认不写文件日志。单文件失败时，界面保留引擎名、退出码和截断后的标准错误（最多 2 KB）。设置中可打开调试日志，写入应用数据目录，不记录图片内容。

## 测试

- Rust：流水线选择、质量参数换算、输出路径约束、同格式「更小才替换」、取消后临时文件清理。用小型固定图片夹具，不依赖界面
- 引擎：每个打包进去的二进制用一张夹具跑通，并核对输出格式的文件头
- 界面：拖放或选择文件、切换格式、开始、取消、失败行仍留在列表里。用应用窗口走一遍，不只用截图

夹具至少包括：普通 JPEG、带透明的 PNG、带文字的截图 PNG、动画 GIF、无宽高的 SVG、已很小的 PNG（优化后不会变小）。
