# Pare 功能文档

文档版本：2026-10-20

这份文档写的是打开软件之后能看见、能点、能得到的东西。引擎参数和安装包见技术文档。

## 功能清单

Pare 第一版就这些功能：

1. 拖入一批图片，或拖入整个文件夹（含子文件夹）。
2. 选择结果写成 WebP、JPEG、PNG，或保持原来的格式。
3. 选择质量档：照片、界面、无损。
4. 指定一个新文件夹存放结果。原图留在原处，一个字节都不改。
5. 开始后逐张处理，列表里看到原大小、结果大小、省了多少、成功还是失败。
6. 保持原格式时，可以打开「允许有损」。关闭时只做不改像素的瘦身。
7. 可以单独关掉 pngquant、zopflipng 这类引擎。
8. 透明图转成 WebP 或 PNG 时保留透明；转成 JPEG 前提示会铺白底。
9. 动画 GIF 可以保持 GIF，或转成动画 WebP。默认不会被抽成一张静图。
10. 处理中可以取消。已写完的留下，没写完的不留半截文件。
11. 断网也能处理。没有账号，没有上传。

没有这些功能：改尺寸、裁切、加水印、滤镜、批量改名、访达右键、自动更新、AVIF、JPEG XL。

## 打开之后的窗口

一个窗口，标题是 Pare。默认大约 960×640，可以拉大。窗口里没有第二套页面跳转，设置和关于从右上角打开，盖在主界面上。

```text
┌ Pare ─────────────────────────────────────────────┐
│ 把图片拖到这里，或选择文件、选择文件夹              │
│ JPEG、PNG、GIF、SVG。结果写到新文件夹，原图不动。   │
├───────────────────────────────────────────────────┤
│ 输出格式   ( ) 保持原格式  ( ) WebP  ( ) JPEG  ( ) PNG │
│ 质量       ( ) 照片        ( ) 界面   ( ) 无损        │
│ 输出到     [ Pare Output              ] [选择文件夹] │
│                                    [开始]           │
├───────────────────────────────────────────────────┤
│ 文件            原大小   结果    变化    状态        │
│ 活动/封面.jpg    1.8 MB  420 KB  -77%   完成         │
│ 活动/标志.png    240 KB  96 KB   -60%   完成         │
│ 活动/动画.gif    3.1 MB    —      —    失败 动画…   │
├───────────────────────────────────────────────────┤
│ 3 张 · 完成 2 · 失败 1 · 省下 1.5 MB                 │
│                          [清空]  [打开输出文件夹]    │
└───────────────────────────────────────────────────┘
                                          [设置] [关于]
```

右上角两个文字按钮：「设置」「关于」。处理过程中这两个仍可打开，但设置里的改动要等下一轮「开始」才生效。

列表上方那一行数字是举例，不是承诺每张图都能压到这个比例。

## 主界面每一块

### 拖放区

没加文件时，窗口上半部分是一块大的放置区，文案是：

> 把图片拖到这里，或选择文件、选择文件夹  
> 接受 JPEG、PNG、GIF、SVG。结果写到新文件夹，原图不改。

下面两个按钮：

| 按钮 | 点下去 |
|---|---|
| 选择文件 | 系统文件窗口，可多选。筛选项为 JPEG、PNG、GIF、SVG，也能切到所有文件 |
| 选择文件夹 | 系统文件夹窗口，选一个目录，里面的图片全部加入，包含子文件夹 |

已经有文件之后，放置区缩成列表上方一条：「继续拖入，或选择文件、选择文件夹」。再拖进来的是追加，不是替换整张表。

拖进不支持的文件时，该行留下，状态为「不支持」，原因写扩展名，例如「不支持 .heic」。其他文件照常加入。

### 输出格式

四个单选，默认 **WebP**。

| 选项 | 这一批每张图会得到 |
|---|---|
| 保持原格式 | 扩展名不变。JPEG 还是 JPEG，PNG 还是 PNG。软件用压缩引擎把文件变瘦；像素在「允许有损」关闭时不变 |
| WebP | 每张都变成 `.webp`。从原图直接编码，不再先用别的有损工具压一遍 |
| JPEG | 每张都变成 `.jpg`。没有透明通道。原来透明的地方变成白色 |
| PNG | 每张都变成 `.png`。再做一次不改像素的 PNG 压缩 |

选 JPEG 时，若列表里有带透明通道的 PNG、或有透明的 SVG，格式这行下面出现一句：

> 透明区域会变成白底。

选 PNG，且列表里有 JPEG 时，出现一句：

> 从 JPEG 转成 PNG 不会更清晰，文件通常会变大。

选「保持原格式」时，这两句都不出现。旁边多出一个开关，见下一节。

选「无损」质量档时，JPEG 这个选项变灰，不能点。鼠标停在上面显示：「JPEG 做不到无损」。若当前已经选着 JPEG，再去点「无损」，输出格式自动改回 WebP。

### 质量

三个单选，默认 **照片**。

| 选项 | 看图的人会得到 | 适合放进去的原图 |
|---|---|---|
| 照片 | 和普通高质量照片接近。渐变、皮肤、风景留着，体积明显下降 | 相机 JPEG、扫描件、产品照片 |
| 界面 | 文字、细线和纯色块尽量不糊。体积通常比照片档大一些 | 截图、界面切图、带小字的 PNG |
| 无损 | 像素与原图一致（转格式时指解码后再无损保存，JPEG 原图本身已经有损失，转出去也不会把损失修掉） | 不能再损失的 PNG、SVG、需要存档的图 |

一批图共用一个质量档。不会自动给照片和截图分档。列表里混在一起时，以用户选的那一档处理全部。

### 允许有损

只有输出格式是「保持原格式」时才显示。默认 **关闭**。

关闭时：

- JPEG：只重新整理文件里的压缩数据，并去掉拍摄信息和定位。画面不变
- PNG：只做无损压缩
- GIF：只做无损优化，帧还在
- SVG：只删掉无用的矢量数据，图形不变

打开时，开关下有一句：「会牺牲一点肉眼不容易看见的细节，换更小的文件。」打开后：

- JPEG：在无损整理之后，再按质量上限 80 压一次
- PNG：颜色很多时减到较少的颜色，但不低于质量 80；会明显变差的图跳过这一步
- GIF：按质量 80 做轻微有损
- SVG：仍然只做无损清理。SVG 没有这个有损步骤

输出格式是 WebP、JPEG、PNG 时，这个开关隐藏。那些格式的损失只由质量档决定，避免同一张图被压两次。

### 输出位置

一行路径加一个「选择文件夹」按钮。

- 还没拖入文件夹时，默认是用户「文档」里的 `Pare Output`
- 第一次拖入或选择的是一个文件夹时，默认改成这个文件夹旁边的「文件夹名-pare」。例如拖入 `活动物料`，输出目录是 `活动物料-pare`，和 `活动物料` 同级
- 之后再追加文件，不自动改输出目录
- 用户点过「选择文件夹」之后，以用户选的为准，不再自动改

输出目录如果位于某个输入文件夹里面，点「开始」时不运行，路径下方红字：「输出文件夹不能放在输入文件夹里面。」避免结果又被当成新的输入。

「开始」时如果目录不存在，就创建它。只是打开窗口、只是选路径，不创建。

### 开始和取消

主按钮只有一个，文案在两种状态间切换：

| 状态 | 按钮 | 行为 |
|---|---|---|
| 空闲，且列表里至少有一张可处理的图，输出路径合法 | 开始 | 按当前格式、质量、输出目录处理所有「等待」的行 |
| 空闲，但没有可处理的图，或输出路径不合法 | 开始（灰色） | 点了没反应 |
| 正在处理 | 取消 | 停止还没写完的图。已经出现在输出文件夹里的完整文件保留 |

开始之后，格式、质量和输出路径锁定，要等这轮结束或取消后才能改。设置窗口里的改动也是下一轮才生效。

### 列表

有文件后，拖放区下面是表格。列从左到右：

| 列 | 内容 | 例子 |
|---|---|---|
| 文件 | 相对路径。单张文件只用文件名 | `活动/封面.jpg` |
| 原大小 | 输入文件字节数，自动用 KB 或 MB，一位小数 | `1.8 MB` |
| 结果 | 写出的文件大小。还没写完是「—」 | `420 KB` |
| 变化 | 变小写 `-77%`，变大写 `+12%`，相同写 `0%` | `-77%` |
| 状态 | 见下表 | 完成 |
| 说明 | 引擎名或失败原因。没有则空着 | `jpegtran` |

每一行右侧有「移除」。只从列表去掉，不删磁盘上的原图，也不删已经输出的文件。正在处理的那一行不能移除，按钮灰色。

点一行不打开预览。第一版没有原图和结果的并排对比图。

底部一条汇总，处理中和结束后都在：

> 12 张 · 完成 9 · 未变小 1 · 失败 1 · 等待 1 · 省下 4.2 MB

「省下」只加总状态为「完成」并且结果更小的那些字节。变大的不从这里扣掉，变大的比例留在该行的「变化」列。

底部右侧两个按钮：

| 按钮 | 行为 |
|---|---|
| 清空 | 清空列表。不删除原图，不删除输出文件夹里的文件。处理中不可用 |
| 打开输出文件夹 | 用系统文件管理器打开当前输出目录。目录还没创建时按钮灰色 |

### 状态

一行只会是下面其中一种：

| 状态 | 用户看到的意思 | 输出文件夹里 |
|---|---|---|
| 等待 | 已加入，还没轮到 | 还没有这个文件 |
| 处理中 | 正在压或正在转 | 还没有这个文件 |
| 完成 | 已经写好 | 有完整的新文件 |
| 未变小 | 保持原格式时，怎么压都不比原图小，所以复制了一份原图过来 | 有一份和原图内容相同的文件 |
| 已用第一帧 | 动画 GIF，并且设置里开了「只用第一帧」 | 一张静图 |
| 不支持 | 扩展名不处理 | 没有 |
| 失败 | 没能写出可用文件。说明列有原因 | 没有半截文件 |
| 已取消 | 取消时这张还没写完 | 没有半截文件 |

失败原因用短句，直接写在说明列，例如：

- 动画不能变成单张静图
- 没有写入权限
- 磁盘已满
- 这张图无法读取
- 缺少引擎 cwebp

## 四种输出，各得到什么

下面用同一批文件说明。这批文件是：

```text
活动物料/
  封面.jpg      一张产品照片
  界面.png      一张带透明的界面切图
  演示.gif      一个动画
  标志.svg      一个矢量标志
```

### 保持原格式，允许有损关闭

输出目录 `活动物料-pare/`：

```text
封面.jpg     画面与原来一致，拍摄信息和定位被去掉，文件通常稍小
界面.png     画面一致，文件往往小一截
演示.gif     帧数不变，文件小一些或不变
标志.svg     图形一致，删掉编辑器留下的无用信息
```

某一张压完不比原来小，状态是「未变小」，输出目录里仍有同名文件，方便整包拿走。

### 保持原格式，允许有损打开

在上一节的基础上，照片和颜色很多的 PNG、GIF 会再小一截，细看可能有轻微色带或色块。SVG 没有进一步的有损。界面上能看见这个开关是开的。

### WebP，照片档

```text
封面.webp     由封面.jpg 直接变成 WebP
界面.webp     透明还在
演示.webp     动画还在
标志.webp     按矢量自己的尺寸变成一张 WebP。没有尺寸时宽度 1024
```

这四张都不会先变成一个更小的 JPEG 或 PNG 再转 WebP。

### JPEG，照片档

```text
封面.jpg
界面.jpg      透明处是白底。开始前界面已经提示过
标志.jpg      透明处是白底
演示.gif      这一张失败，说明列写「动画不能变成单张静图」
```

输出文件名如果和上面「保持原格式」的结果撞名，不会互相覆盖，见下文「文件名」。

### PNG

```text
封面.png      能打开，清晰度停在原来的 JPEG，文件常常比 jpg 大
界面.png      透明还在
标志.png      透明还在
演示.gif      默认失败，原因同上
```

## 文件名和文件夹

输出保持拖入文件夹里的相对路径。

```text
活动物料/主视觉/封面.JPG   →   活动物料-pare/主视觉/封面.webp
```

只改扩展名，不改主文件名的大小写习惯：`封面.JPG` 变成 `封面.webp`。

同一输出路径已经有文件时，不覆盖。在扩展名前加 `-2`、`-3`：

```text
封面.webp
封面-2.webp
```

单张拖入、没有共同的父文件夹时，文件直接放在输出目录根下。

跳过、不加入列表的文件：

- 名字以 `.` 开头
- `.DS_Store`、`Thumbs.db`
- 文件夹本身

## 一张图实际怎么处理

用户不需要操作这些步骤，列表只显示等待、处理中、完成。写在这里是为了说明「完成」之前发生了什么。

保持原格式的 PNG，允许有损关闭，Zopfli 开着：

1. 复制到临时目录。
2. 用 oxipng 做无损压缩。比当前更小就留下。
3. 用 zopflipng 再试。超过 60 秒就停，留下这一步之前更小的那份。
4. 和原图比。更小就写入输出目录，说明列写最后一次让文件变小的引擎名。不大不小或更大，就复制原图，状态「未变小」。

保持原格式的 JPEG，允许有损打开：

1. jpegtran 做无损整理并去掉元数据。
2. jpegoptim 按质量上限 80 再压。
3. 两步里更小的那份和原图比，规则同上。

转成 WebP 的照片：

1. 不跑 jpegoptim、pngquant。
2. 直接把原图编成 WebP，质量 85。
3. 不论比原图大还是小，都写入。变大时变化列是正的百分比，状态仍是「完成」。

## 设置

点「设置」打开一个面板，不是单独的窗口。分组如下。

**处理**

| 项 | 默认 | 作用 |
|---|---|---|
| 同时处理 | 4 | 可选 1 到 8。数字越大越快，也越占 CPU |
| GIF 只用第一帧 | 关 | 打开后，动画 GIF 在输出 JPEG、PNG 时不再失败，只导出第一帧，状态为「已用第一帧」。输出 GIF 或 WebP 时这个开关无效，动画保留 |
| 调试日志 | 关 | 打开后，失败详情写到本机应用数据目录。不记录图片内容 |

**引擎**（只在「保持原格式」时用到）

每一项是开关，默认全开。后面有一行人话，而不是只写程序名。

| 开关上的名字 | 说明文字 | 关掉之后 |
|---|---|---|
| PNG 无损压缩 | oxipng | 同格式 PNG 少这一步。转成 PNG 时这一步仍然会做 |
| PNG 减色 | pngquant，仅允许有损时 | 颜色多的 PNG 不再减色 |
| PNG 慢速压缩 | zopflipng，单张最多 60 秒 | 不再等这一步，PNG 处理更快，文件可能稍大 |
| JPEG 无损整理 | jpegtran，并去掉拍摄信息和定位 | 同格式 JPEG 不再做无损瘦身 |
| JPEG 有损压缩 | jpegoptim，仅允许有损时，质量上限 80 | 不再按 80 再压一次 |
| GIF 优化 | gifsicle | 同格式 GIF 原样复制，状态按「未变小」处理 |
| SVG 清理 | svgcleaner | 同格式 SVG 原样复制，状态按「未变小」处理 |

关掉全部相关引擎时，这些文件都会以「未变小」复制到输出目录，批次仍算跑完，不叫失败。

设置改完即写到本机，不需要保存按钮。不上传。

## 关于

面板里只有这些文字：

- 名称：Pare
- 版本号
- 图片只在这台电脑上处理，不会上传。
- 引擎列表：每个引擎的名字和版本，例如 `cwebp 1.x`、`oxipng x.x`

没有「检查更新」，没有网站账号，没有许可证输入框。

## 几件具体的事

**只想把照片变成较小的 WebP**

拖入文件夹，确认格式是 WebP、质量是照片，看一眼输出路径，点开始。到 `活动物料-pare` 里取 `.webp`。原文件夹还是原来的 jpg。

**截图要小，但字不能糊**

输出格式 WebP，质量选界面。不要开「允许有损」，这个开关在 WebP 下也看不见。

**已经是 PNG，只想瘦一点，格式不变**

输出格式选保持原格式，允许有损保持关闭，开始。列表里「未变小」的那些本来就压不动，输出里仍有副本。

**同一批里既有照片又有动画**

可以一次拖入。输出 WebP 时照片和动画都会变成 WebP，动画继续动。输出 JPEG 时动画那几行失败，照片照常完成，底部汇总里能看见失败张数。

**处理到一半不想等了**

点取消。已经完成的文件留在输出文件夹。正在写的那张不会留下半个文件。列表里没跑完的行变成「已取消」。再点开始，会处理仍然处于「等待」的行；「已取消」的行不会自动重跑，需要重新拖入。

**电脑没有网络**

可以拖入、可以选择文件夹、可以开始。失败原因不会是「无法连接服务器」。

## 第一版明确没有的

- 拖动滑块自己填质量数字。只有照片、界面、无损三档
- 处理前或处理后并排看图
- 改宽度、改高度、裁切
- 保留拍摄信息、地理位置。同格式 JPEG 和转成 WebP 时都会去掉
- 覆盖输出目录里的同名文件
- 记住上一次的文件列表。关掉窗口，列表清空，设置还在
- 访达、资源管理器里的右键菜单
- 命令行
- 把 HEIC、TIFF、BMP、PDF 加进列表后自动转换。这些行是「不支持」
